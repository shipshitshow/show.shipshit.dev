# Three thumbnail test variants

## Channel context

Use the user's channel profile and actual source asset. For Ship Sh*t Show, read [the bundled profile](references/channel-profile.md); viewers using another channel should provide their audience, voice, formats, links and visual references. A profile is context, not permission to publish, upload footage, buy generation or contact a partner.

For the bundled show, read the canonical brand kit and inventory linked in the profile. Use its thumbnail rules and appropriate authorized assets; draft boards are composition references, not final artwork or new source photographs. Place the asterisk exactly as [the placement table](https://github.com/shipshitshow/vault/blob/master/brand/placement.md) says, from the same three SVG masters; never redraw it or pick a corner or size by eye.

Determine live, edited recap or Short, the delivered thesis, supplied topic/brand references and whether the user wants new concepts or a surgical edit. For a surgical edit, preserve all unrequested elements; do not redesign the asset to satisfy default style.

Thumbnails lead with the topic and contain no host faces or likenesses: do not use host photographs or character references, and do not prompt for people. Vary the topic treatment (official logo, source-grounded visual, short text) instead. For Ship Sh*t Show, the exact six-arm signature always sits top-right inside the profile’s format-specific safe margins: equal top/right for 16:9, larger top than right for 9:16 Shorts. Use the supplied vector master in the final composite; subtle scene-matched material/lighting may integrate it without changing its silhouette, base color or safe placement. Livestream thumbnails use the red signature; edited-video thumbnails use the white (on dark) or black (on light) signature.

For a new test set, return **exactly three** distinct hypotheses. Examples: decisive outcome, firsthand workflow proof, and meaningful tradeoff. Distinguish them enough to learn something while preserving the same truthful viewer promise. Do not label a prompt a proven winner. If testing thumbnails alone, hold the title fixed; if the user chooses combined tests, label each title/thumbnail pair explicitly.

Each variant includes: hypothesis; intended viewer inference; composition/crop; topic and logo references (no host references); restrained palette; optional short text with exact spelling; complete generation prompt; exclusions; small-size review; and suggested first/default candidate if the test is inconclusive. Use real proof or a clearly illustrative metaphor rather than fabricating a product screenshot, endorsement or benchmark.

Inspect the current asset before edits. Use the available image tool for actual generation, preserving transparency when requested. For motion or editable composites use an appropriate installed tool/plugin. A prompt-only request does not authorize spending on generation or publishing to YouTube.

Read [the prompt and testing contract](references/prompt-output-format.md). YouTube's current testing supports up to three candidates on eligible long-form uploads/completed live archives, not Shorts or scheduled live streams; watch time, not CTR alone, determines its result. Recheck [current eligibility and specifications](https://support.google.com/youtube/answer/16391400?hl=en). Keep Shorts cover/upload/frame selection as a separate workflow: check the current desktop Studio/account controls and actual grid/player crops, and do not promise native A/B support. The profile links checked guidance and distinguishes house safe margins from video-ad templates.
