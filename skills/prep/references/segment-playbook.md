# Segment playbook

How a board is shaped so the hosts can talk naturally and still land the title's promise. The numbers in this file come from the 10 November 2026 audit of the channel (35 livestreams, 34 videos, the full 3 November stream). They are direction, not proof.

## Shape of a show

| Part | Budget | What it does |
| --- | --- | --- |
| Cold open | about 1 minute | First sentence, then the three questions; the first useful point by about 45 s |
| Segments | at most 3, 10–15 minutes each | Each answers part of the title's promise |
| Close | about 5 minutes | One verdict per host, the viewer question answered, show ends here |
| After the show | up to 5 minutes, after the verdicts | Catch-up, housekeeping, off-title items from the board's after-show block |

Fit these to the planned total; the close is the last thing to cut.

## One title, one promise

Write the title's promise as one sentence before choosing segments. A segment stays only if it moves the answer forward. On 3 November the title topic was named for the first time at 8:20 and the viewer's question was answered at 49:00; that is the pattern to avoid. Items that do not serve the promise go in the board's after-show block, in the next episode's backlog, or out.

## Segment card

Each segment, in this order:

1. **Question:** the part of the title's promise this segment answers.
2. **Story:** one firsthand story per host with one number each, labelled as theirs. `No firsthand: ask` when a host has none; then cut it or run it as an open question.
3. **Source line:** one line, link included, that both hosts have read. If neither read it, drop it.
4. **Stance:** each host's own one-line verdict, `Split` where they differ, `Agree` where they match, `Open` where a host has no view. Never write a view for a host.
5. **Challenge:** the strongest opposing case. When both hosts agree, this is the sceptical customer's question, asked by one of them.
6. **So what:** what the viewer decides differently.
7. **Producer notes:** time budget, re-hook, chat question, what to open on screen, exit cue.

Talking points stay terse (2–5 bullets under 12 words). The story and stance lines are cues, not wording.

## The stance check

Do it before the show, in writing, one line per host per segment. Where the lines differ, that is the segment, and it gets the time. Where they match, one host asks what a sceptical customer would ask: what did it cost, what broke, would you ship it. Plan the question, not the disagreement. If a host honestly agrees, the board says so; the audit found a median 44.5% of speaker turns opening with yeah, yes or exactly against 6.5% opening with push-back, and the cure is a better question, not staged conflict.

## Re-hooks and chat

- **Re-hook every 8–10 minutes.** One sentence: what we have answered, and what the viewer still gets ("we still have not answered X, and that is next"). Write it as a cue in Producer notes with the planned elapsed time.
- **One chat question per segment.** Read it aloud. If the chat is quiet, use a planted question from the hosts' own notes. On 3 November no chat question was taken.

## Live builds and demos

Live builds produced up to 588 seconds without speech. Either prepare what each host says while it runs (what we expect, what would worry us, what we did last time), or run the wait off air and show the result. Prepare the recovery path and the recorded fallback; mark the slot unavailable if neither exists.

## Close

Answer the title's question using only what the show established, then each host says in one sentence what they would do on Monday. State what remains unknown. End the show on the verdicts, not on "I think it's a nice conclusion". The after-show block follows, labelled, so the replay can end on the verdict.

## After the show

Record actual segment timing, time to the first claim, the host verdicts that differed, chat questions taken, and demo outcomes. Keep them for the weekly review so each show can be compared with the previous one.
